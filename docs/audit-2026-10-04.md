## PR validation

Validation uses the exact isolated PR checkout. Database writes use only an isolated loopback PostgreSQL fixture; no production database changes, paid AI calls or external messages are part of these checks.

Verified on the isolated PR checkout:

- `npm run lint`, `npx tsc --noEmit`, `npm run build` and `npm run test:content` passed.
- 19/19 registered tests passed with explicit isolated `SECURITY_TEST_DATABASE_URL`; the suite safely skips the integration test without that opt-in.
- 396/396 public/auth page visits (66 routes × EN/ZH/BM × desktop/mobile) returned HTTP 200, with zero final page errors, horizontal overflow, broken decoded images or visible unnamed inputs.
- 176/176 protected-route checks passed: 25 anonymous, 100 four-role HTTP checks, and 51 master-admin localized mobile pages.
- 27/27 interaction checks and 4/4 localized draft/auth state checks passed.
- Production-mode auth/API checks rejected four legacy default password pairs, accepted rotated fixture passwords, enforced account quotas despite forged forwarding headers, and failed closed when quota storage was absent. Invalid chat bodies returned localized 400/413; unconfigured AI returned 503 without a provider request.
- A disposable schema-only database verified additive seed/bootstrap behavior and preservation of accounts, passwords, sessions, administrator edits, publication states and intentionally deleted content.
- Separate disposable PostgreSQL clusters verified the quota schema/migration and CLI policy helper: RLS enabled, no client policies, 20 client operations denied, owner read/write access retained, direct URL precedence/fallback and repeated execution safe.

Browser process exits and preview artifact replacement affected early attempts. Those attempts were retained locally and only affected routes were retried after restarting the preview; final coverage contains 396 successful visits. Raw screenshots, local credentials and machine-specific browser scripts are excluded from this repository.

The final scope contains audit fixes and regression helpers. It excludes concurrent artwork replacements, new photography, homepage redesign and Blender backups.

## Deployment prerequisite

Apply the additive [rate-limit table migration](../src/db/migrations/20261004_rate_limit_buckets.sql) before enabling the changed application, or run `npm run db:push` using the existing deployment's normal database procedure. The schema now includes both `src/db/schema.ts` and `src/db/rate-limit-schema.ts`; `db:push` automatically applies RLS and revokes client grants for the backend quota table. Guarded authentication/chat operations fail closed when quota storage is unavailable.

For existing installations, rotate/remove legacy demo credentials and revoke old sessions. Production sign-in rejects original default passwords; a new owner must use explicit bootstrap credentials. See [README](../README.md).

Unknown packaging/formulation/bundle details require brand confirmation. Public concept labels and consultant confirmation text represent these gaps without invented facts. Browser semantic/layout checks are not a formal WCAG certification.
